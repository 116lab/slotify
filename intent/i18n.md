## Judgment
- UI language covers chrome strings only and is decoupled from content and Hugo's
  multilingual system: switching language never changes the route or refetches content.
  - `switching language changes neither the route nor the loaded content`
- The initial locale is a valid stored choice, else the browser's language when the site
  ships it, else the default (the first registered locale).
  - `initial locale detection › the browser language is used when nothing is stored`
  - `initial locale detection › a stored locale code wins over the browser language`
- Unknown locale codes are ignored, so a stale stored value or bad input cannot desync
  the UI.
  - `initial locale detection › an unknown stored code is ignored`
- A failed locale-table fetch degrades to the key/English fallback rather than blocking
  the mount.
  - `the app still mounts when the locale tables fail to load`
- Storage access is guarded: storage being unavailable (private mode, blocked storage)
  never breaks boot; preferences just are not persisted that session.
  - `the app boots and switches theme when storage throws`
